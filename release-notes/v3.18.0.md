## New: analyze a book before optimizing

The local interface has an **Analyze without changes** button. It runs the read-only doctor and shows the file size, the share of images, optimization hints, accessibility findings, and whether the book can be optimized at all (DRM or internal DTD declarations block it). Nothing is modified and no optimized EPUB is produced; the complete diagnosis downloads as JSON. All five interface languages are covered.

## New: image quality guard

Quality options such as `--jpg-quality` and `--png-quality` apply to every image, but some images tolerate them much worse than others. Each lossy encode (recompression or PNG-to-JPEG conversion) is now compared with its source using SSIM:

- An encode below `--min-image-ssim` (default `0.85`) is redone at higher fidelity. If that is still below the threshold, or not smaller, the original image is kept byte-for-byte and a PNG is not converted.
- An intended `--max-image-dim` downscale is not counted as loss. Transparent images are checked on white and on black.
- Scores and outcomes appear in JSON reports (`imageQuality`) and in HTML reports.
- `--min-image-ssim 0` disables the guard and restores the previous behavior.

## New: accessibility checks in doctor mode

`--doctor` adds an `accessibility` section: images without a text alternative, documents without a declared language, missing EPUB Accessibility 1.1 metadata, and page breaks without a page list. EPUBCheck validates the EPUB format, not accessibility, so these findings were previously invisible. They are heuristics, not a conformance audit: use a dedicated checker such as Ace by DAISY and a manual review before claiming conformance. The optimizer does not add or change accessibility metadata or alternative text.

## Improvements

- **Repackaging no longer grows unchanged files.** A file whose content is unchanged keeps the source EPUB's compressed bytes when they are smaller than a fresh level-9 deflate, after verifying that they decompress to the same content (size and SHA-256). Incompressible files are stored instead of deflated. This fixes Lossless output that could be slightly larger than its input.
- **Interface downloads are named after the book**: `<title>-optimized.epub` and `<title>-report.html|json`, instead of `optimized.epub` for every book.
- `epub-optimizer-ui --help`, its startup messages and the interface's API messages are in English, like the main CLI. The page itself was already translated and is unchanged.

## Compatibility

- **The image quality guard is on by default.** Output changes only for images whose default encode scores below 0.85: they come out at higher quality and larger, or unchanged. Other images and all text processing are unaffected.
- JSON reports gain `imageQuality`; doctor reports gain `accessibility`. Existing fields, exit codes and optimization `risks` are unchanged.
- The archive is written by a new internal ZIP writer. `mimetype` is still first, stored and without an extra field; every candidate is still validated by EPUBCheck before publication. Symbolic links in the working directory are refused.
- Interface API: `stage` and `error` strings are English, download file names changed, and job JSON gains `mode` (plus `diagnosis` for analysis jobs). Error and finding codes are unchanged. Requests without `mode` behave as before.
- The Node.js API exports `ImageQualityRecord` and `ImageQualityOutcome`, and `ContentProcessingOptions` gains an optional `onImageQuality` callback.

## Validation

732 unit tests pass with two existing skips. Feature PR and post-merge CI pass on Node 22/24, including installed-package checks and EPUBCheck E2E, which now runs a real analysis job through the interface. Native Linux AMD64/ARM64 Docker tests run the same interface workflow and the existing workflows.

Measurements below are single local runs on one 60 MB Pages-exported book (macOS ARM64, Node 25) and are not general guarantees:

- Lossless: output went from 11.7 KB larger than the input to 559 bytes smaller, with identical decompressed content.
- Balanced with the guard: all 13 lossy encodes scored between 0.895 and 0.959, so no image changed and the output content was identical to a run with the guard disabled. Measuring added about 1 s to a 6.6 s run.
- Analysis in the interface was checked in a browser in English and French, light and dark themes, desktop and 375 px widths.
