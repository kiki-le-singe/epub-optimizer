## Validated Node.js API

- Route exported `optimizeEPUB()` calls through the same optimization pipeline as the CLI. Text and content integrity checks, repair/author passes, EPUBCheck validation and transactional output publication now apply to normal API calls too.
- Preserve the input and any existing output when API validation fails or times out. Keep extraction diagnostics and discard unpublished candidates on failure; clean temporary files only after successful publication.
- Retain content-only preparation with `skipPackaging: true`: it does not create, replace or validate an output EPUB. Copy caller options before applying feature-specific adjustments.

## Diagnostic accuracy

- Detect internal DTD subsets and content DRM before interpreting XML in doctor mode. Report explicit optimization blockers in both console output and JSON, including DTDs in package files or resources with nonstandard extensions. Font obfuscation alone remains inspectable.
- Omit detailed content metrics when unsupported EPUB semantics prevent analysis. A blocked diagnosis includes `analysisComplete: false`, `optimization.blocked: true`, structured blockers and risks. A successful diagnosis still does not certify EPUBCheck validity.
- Calculate image archive share from compressed ZIP payload bytes, counting each resource once even when referenced by multiple manifest items. Keep uncompressed image bytes separately; extracted-directory inspection without ZIP metadata reports an unavailable compressed share instead of a misleading percentage.

## Compatibility

- Normal Node.js API optimization now requires Java and EPUBCheck, and can reject content or validation failures that the previous lower-level API did not check. CLI flags and presets are unchanged.
- Doctor JSON adds `analysisComplete`, `optimization` and `images.compressedBytes`. Consumers must check `analysisComplete` before reading detailed metrics, which are omitted for blocked books. `images.archivePercent` now represents compressed archive share and can be `null` when ZIP metadata is unavailable.
- Doctor exit code 0 means diagnosis completed, even when it reports optimization blockers. The optimization command continues to reject these books.
- Dependency versions, the lockfile and supported Node.js versions are unchanged.
