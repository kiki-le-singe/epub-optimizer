## Improvements

- **Usable opt-in font subsetting:** `--fonts` now uses the included, pinned HarfBuzz WebAssembly engine instead of requiring a separate legacy fontmin installation. Eligible TTF, OTF, WOFF and WOFF2 fonts retain their container format, hinting, layout features, embedding permissions and copyright/license text.
- **Conservative character collection:** nested XHTML, navigation, SVG, attributes and manifest-declared text resources are considered regardless of filename extension. Unicode normalization and case equivalents are included without rewriting the publication's text. Uncertain generated/imported CSS text, scripts, mathematical content and external SVG text preserve fonts rather than guessing glyph coverage.
- **Isolated processing and safe replacement:** each font runs in a disposable process with a deadline, V8 heap cap and sampled RSS monitoring. Smaller candidates replace originals atomically; processing failures and absent size benefits retain original font bytes. Candidate cleanup verifies ownership and aborts optimization if safe cleanup is impossible.
- **Regression coverage:** original generated font fixtures exercise actual glyph outlines, substitutions and kerning. Additional tests cover Unicode, unsupported/restricted fonts, worker timeout/memory handling, atomic replacement and cleanup ownership. CLI, installed-package API and Docker E2E cases exercise the bundled engine and default font preservation.

```bash
# Optional; fonts are never subset by default or enabled by a preset.
pnpm optimize -i book.epub -o book-optimized.epub --fonts
```

## Compatibility and limits

- Default processing, presets, public API argument shapes and JSON report formats are unchanged. This release makes the existing `--fonts` option functional with bundled runtime dependencies; it does not publish the package to npm.
- All fonts remain byte-for-byte intact when encryption metadata is present. Variable, color, mathematical, Graphite, collection and embedding/subsetting-restricted fonts remain unsupported and are preserved.
- Processing is sequential within each book, with limits on font count, input/expanded size, text resources and collected code points. A worker has a 10-second deadline and 128 MiB V8 heap cap. RSS is sampled every 100 ms against a 256 MiB budget: this is **not an OS-enforced hard memory limit**, and transient peaks can exceed it. Budgets apply per book/worker, not across concurrent API calls.
- Resource monitoring supports Linux and macOS. If monitoring is unavailable, fonts are preserved. Other platforms conservatively skip this optional feature. See the [font subsetting documentation](https://github.com/kiki-le-singe/epub-optimizer#font-subsetting) for the complete limits and eligibility rules.
- Uncertain content and processing failures produce report warnings; existing `--strict` behavior can reject those warnings while preserving an existing final EPUB. Known unsupported fonts and absent size benefits are informational skips. An unsafe candidate cleanup aborts even without strict mode.
- EPUBCheck validates the final candidate but does not certify rendering on every reading system. Size savings and resource use depend on the book; font processing adds worker startup and memory overhead.
- Node.js 22.12 or newer and Java 17 or newer remain supported. Docker includes Java and the pinned validator; local package consumers still configure EPUBCheck separately.

## Validation

The local suite passes 588 tests with one existing skip; coverage thresholds are unchanged. PR and post-merge CI pass on Node 22/24, including installed-package and EPUBCheck E2E checks. All eight Docker/Compose E2E cases and the image vulnerability policy pass on native Linux AMD64 and ARM64. CI uses generated EPUB/font fixtures, not user books or system fonts.
