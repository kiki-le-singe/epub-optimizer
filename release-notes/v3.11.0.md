## Improvements

- **Typed Node API:** production builds emit TypeScript declarations and advertise the package's root types entry. Consumers can import `Args`, `Preset`, `OptimizeOptions`, processing hooks and report types alongside the existing API functions.
- **Readable application code and error stacks:** the optimizer's own JavaScript is compiled without application minification, retaining comments and useful file/line/column locations. JavaScript embedded inside EPUBs is still minified normally.
- **Verified local packages:** `pnpm pack` runs a clean build through `prepack`, including declarations. Package contents are limited to compiled JavaScript/types, README, license and the pinned EPUBCheck installer. Repository metadata is included; local books, reports, implementation TypeScript and tests are excluded.
- **Installed-consumer checks in CI:** Node 22/24 jobs install the real tarball with production dependencies in an isolated consumer, audit those dependencies, compile positive and negative strict TypeScript examples, and exercise the installed CLI/API, deep imports, readable stacks and validator failure protection.

```bash
# From the source checkout; creates a local archive, not a registry publication.
pnpm pack --out /tmp/epub-optimizer.tgz
```

## Compatibility

- CLI options, presets, EPUB transformations, JSON report formats and validation/publication safeguards are unchanged. No dependency versions or lockfile entries change in this release.
- Existing root and deep ESM imports remain available; the main and CLI entry paths are unchanged. `Args` still describes fully resolved API processing options. The new declarations can reveal incomplete or incorrectly typed arguments previously hidden by an untyped import; no partial-options API or new defaults are introduced.
- The legacy `pnpm minify:safe` development command remains an explicit opt-in, outside the normal build. Packing rebuilds readable JavaScript and declarations first.
- The tarball does not bundle Java or the EPUBCheck JAR and does not download them during installation. Configure `EPUBCHECK_PATH` for packaged optimization; the included installer retains the pinned version and checksum. Docker remains the distribution with Java and EPUBCheck included.
- Node.js 22.12 or newer and Java 17 or newer remain supported. This GitHub/Docker release does **not** publish the package to npm; local tarball creation and registry publication are separate operations.

## Validation

The suite passes 535 tests with one existing skip. Installed-package checks, full EPUBCheck E2E and Docker/Compose workflows validate the readable build; CI covers Node 22/24 and native Linux AMD64/ARM64 images and security scans. Generated EPUB fixtures are used throughout.
