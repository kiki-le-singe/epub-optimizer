## New in the local interface

- **Optional WebP conversion.** A "Convert images to WebP" checkbox runs the conversion introduced on the command line in 3.19.0. It is off by default, carries the same warning about older reading systems, and is disabled with the lossless preset.
- **Image fidelity results.** After an optimization, the result card shows what the image quality guard measured: how many images were checked, the lowest score among the images it changed (rounded down, so it never overstates fidelity), and how many images were converted to WebP, re-encoded at higher quality, or kept unchanged.
- **Analysis** shows the new WebP finding described below.

All new text is available in the five interface languages.

## New doctor hint for WebP images

`--doctor` reports a `webp-images` finding when a book already contains WebP images: `info` in an EPUB 3 package and `warning` otherwise, because WebP is a core image type only since EPUB 3.3 and older reading systems may not display it.

## Watched folder defaults

`compose.watch.yaml` and the image written by `scripts/setup-watch.sh` pinned 3.13.0 and 3.15.0 while the documentation described newer releases. Both now pin the tested 3.19.0 index digest, so a fresh watcher gets crash recovery (3.16.1) and everything released since.

## Compatibility

- Optimizer output is unchanged from 3.19.0 for the same options.
- Interface API: `POST /api/jobs` accepts `webp=1`. Any other value or a repeated parameter is refused with `invalidOption`, and `webp=1` with `preset=lossless` with `webpLossless`. Analysis jobs ignore it. Job JSON gains `webp` and `summary.images`. Requests without `webp` behave as before.
- Doctor reports can carry one more risk code, `webp-images`. Existing fields and exit codes are unchanged.
- An existing `.env.watch` keeps the image it names. A fresh `docker compose -f compose.watch.yaml up` without an image override now pulls 3.19.0 instead of 3.13.0. The watcher's job directory names include the tool version, so books already processed by an older default are processed again into new revision directories; earlier outputs remain.
- README anchors such as `#webp-conversion` moved to the guides. External links to an old README anchor land at the top of the README. The npm package still ships `README.md` only; on npmjs.com its links to `docs/` resolve to the repository.
- Release automation: after pushing the candidate image index, the Release workflow rereads it for up to one minute when the registry answers "not found". Any other registry error still stops the draft before a tag is created. `pnpm release:examples <version> <digest>` updates every installation example after a release.
