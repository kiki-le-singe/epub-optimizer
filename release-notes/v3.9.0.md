## Improvements

- **Structured EPUBCheck diagnostics:** JSON and offline HTML optimization reports now include validation totals, message codes, severity, suggestions and source locations when available. Diagnostics are also retained when validation fails or times out. The validator's native exit status and strict warning policy still determine whether the candidate EPUB can be published; missing or unreadable JSON details retain the existing text-based fallback.
- **Isolated diagnostic collection:** processing steps collect explicit warnings and errors in their own asynchronous scopes without replacing global `console` methods. Concurrent API calls keep separate diagnostics, and completed steps stop collecting late callbacks. Nested step diagnostics remain visible to the enclosing operation. Batch processing remains sequential.
- **Author navigation repair:** EPUB3 TOC discovery handles alternate namespace prefixes, multiple type tokens, accessibility roles and plain navigation lists without failing on an unsupported CSS namespace selector. Regression tests cover author structure updates and repeated processing while preserving chapter content and reading order.
- **Documentation and regression guards:** the README explains the sample book's actual image savings and the scope of memory measurements. Unit coverage thresholds are raised, and generated-fixture tests protect author operations and diagnostic reporting.

## Compatibility

Existing CLI options, presets and sequential batch defaults are unchanged. Candidate EPUBCheck validation still happens before output publication; validation failure or timeout preserves an existing output EPUB.

JSON optimization reports gain an optional `validation` object. Consumers should accept these additional fields. When structured details are unavailable, its `source` identifies text fallback or unavailable diagnostics. Doctor report fields are unchanged.

**Custom API processing hooks:** use the newly exported `reportWarning(...args)` and `reportError(...args)` helpers from the Node.js entry point to include diagnostics in step reports and strict checks. Ordinary `console.warn` and `console.error` calls still print, but are no longer intercepted or treated as processing diagnostics. Hooks that relied on that interception must migrate to the helpers; thrown exceptions continue to fail the operation.

Node.js 22.12 or newer remains supported. Java and EPUBCheck are still required for packaged optimization through both the CLI and API.
