## New: watched folders

Keep EPUB Optimizer running and drop books into an inbox:

```bash
mkdir -p inbox optimized
pnpm optimize --watch inbox --output-dir optimized --strict --clean
```

- `--watch` polls a directory once per second, including books already present, and processes top-level EPUB files sequentially through the existing text/content integrity and candidate EPUBCheck validation pipeline.
- Each successful job receives its own directory with `optimized.epub`, JSON/HTML reports and a completion record. The source name, content, tool version and settings identify the job; changed books/settings get separate outputs. Original books and previous successful outputs are retained.
- Restarting skips successfully completed jobs after checking their output checksum. Individual failures do not block later books; an unchanged failed input is attempted once per session and can be retried after changing the file or restarting.
- Processing uses a private input snapshot. Ctrl+C or SIGTERM stops accepting books and lets the current optimization finish. An exclusive output-directory lock prevents simultaneous watchers from using the same output location.
- The Node.js API exports `runWatch(args, { signal })` and self-contained cancellation/report types, compatible with consumers that do not install DOM or Node development typings.

## Compatibility and operational limits

- Existing single-book/batch commands and preset defaults are unchanged. Watch mode is opt-in, requires `--output-dir`, and writes its per-book JSON/HTML reports automatically. It cannot be combined with batch/doctor or explicit input/output/temp paths.
- Input and output roots must be separate, non-nested real directories. Nested inputs, empty files and symbolic links are ignored. Unsafe output targets, altered completion records and replaced outputs are refused.
- The default quiet interval is three seconds; `--watch-settle-ms` accepts at least 1000 milliseconds. **A quiet interval does not prove a transfer has finished.** Copy to a name such as `book.epub.part`, then rename to `book.epub` after the transfer completes.
- Author configuration is snapshotted at startup; restart after editing it. Reports refer to the private input snapshot; the completion record records the original inbox path.
- Watch runs locally or in Docker with mounted folders. The output must be writable by the container user; allow sufficient stop grace time for the current book. After a crash or forced termination, confirm no watcher is running before removing a stale `.epub-watch.lock`.
- Successful outputs and records persist until removed by the user. This is a local processing feature, not an upload service. No npm publication is included.
- Development-tool updates include TypeScript ESLint 8.72.2, Vite 8.3.7, setup-java 6.2.0 and docker/login-action 4.8.0. Actions remain pinned by full commit SHA; production dependency versions and release permissions are unchanged.
